# Phase 1 Data Model: Agent Creation Tools

## Entity: Creation Tool Grant

A tool name stored in an agent definition's existing `tools`/`custom_tools` list.

| Field | Type | Rules |
|-------|------|-------|
| `name` | string enum | `create_skill` or `create_agent`; each is independent. |

The grant has no owner field. At session creation, exact saved names are resolved through the tool
registry and the resulting closure captures the authenticated `user_id`. Neither name is added to
new or existing agents by default.

## Entity: User-Owned Skill

Stored in the `user-skills` Cosmos container, partitioned by `/user_id`, through the existing
user-scoped wrapper:

```json
{
  "id": "incident-summary",
  "user_id": "opaque-authenticated-subject",
  "data": {
    "id": "incident-summary",
    "name": "incident-summary",
    "description": "Summarize incident notes into an action report.",
    "content": "# Incident Summary\n...",
    "source": "user",
    "createdAt": "2026-07-10T12:00:00+00:00",
    "updatedAt": "2026-07-10T12:00:00+00:00"
  },
  "created_at": "2026-07-10T12:00:00+00:00",
  "updated_at": "2026-07-10T12:00:00+00:00"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | Equal to skill name and Cosmos item id; lowercase slug, max 64. |
| `user_id` | string | Partition key from authenticated context; never accepted from tool input. |
| `data.name` | string | Same value as `id`; no collision with owner's skills or any global skill. |
| `data.description` | string | Non-empty, max 256. |
| `data.content` | string | Non-empty, max 65,536; never returned in tool result or logged. |
| `data.source` | string | Constant `user`. |
| timestamps | ISO-8601 strings | Generated by backend/repository; not accepted from tool input. |

Global skill documents remain unchanged in `skills` partitioned by `/id`. The owner catalog is the
set union of global documents and documents from exactly one `user_id` partition. Duplicate names
are prohibited, so no shadowing precedence exists.

## Entity: Custom Agent Definition

The existing bare payload remains inside the `custom-agents` `/user_id` wrapper. The canonical wire
shape uses the frontend's established camelCase fields:

```json
{
  "id": "incident-planner",
  "name": "Incident Planner",
  "description": "Builds incident action plans.",
  "systemPrompt": "Create concise, evidence-based plans.",
  "tools": ["create_skill"],
  "skills": ["table-usage"],
  "mcpServers": [],
  "useSearchContext": false,
  "icon": "/favicon.png",
  "starters": [{"label": "Plan", "message": "Create an incident plan."}],
  "temperature": 0.2,
  "agentsAsTools": [],
  "source": "custom",
  "createdAt": "2026-07-10T12:00:00+00:00",
  "updatedAt": "2026-07-10T12:00:00+00:00"
}
```

| Field | Rules |
|-------|-------|
| `id` | Required stable slug/identifier; must equal path/tool identity; unique within owner partition. |
| `name` | Required after trim, max 100. |
| `description` | Optional bounded text using existing management behavior. |
| `systemPrompt` | Required after trim, max `MAX_USER_INPUT_CHARS`; never returned by tool. |
| `tools` | List of exact registered tool names; unknown/unavailable names fail creation. |
| `skills` | Each resolves in global plus invoking-owner catalog; unresolved names fail creation. |
| `mcpServers` | HTTP-only custom-agent definitions satisfying existing name/URL/auth safety rules. |
| `useSearchContext` | Boolean with existing default. |
| `icon` | Existing safe/default presentation value. |
| `starters` | Existing label/message list shape and bounds. |
| `temperature` | Number in `[0.0, 2.0]` or existing default. |
| `agentsAsTools` | Existing reference shape; targets resolve only from built-ins and invoking owner's custom agents; no self/direct cycles. |
| `source` | Constant `custom`; caller cannot use the tool to create a built-in or override. |
| timestamps | Backend-generated. Tool input cannot set storage bookkeeping. |

Management updates preserve `createdAt` and refresh `updatedAt`. Runtime `create_agent` performs
atomic create only and never merges/upserts.

## Entity: Validation Issue

```json
{"field": "skills[0]", "reason": "Skill could not be resolved."}
```

Issues use public field paths and corrective reasons. They never reveal another owner, whether a
cross-user id exists, raw provider errors, or rejected secret values.

## Entity: Tool Creation Result

Created variant:

```json
{
  "status": "created",
  "kind": "skill",
  "id": "incident-summary",
  "name": "incident-summary",
  "message": "Created skill 'incident-summary'."
}
```

Error variant:

```json
{
  "status": "error",
  "kind": "agent",
  "code": "validation_error",
  "message": "The agent definition is invalid.",
  "retryable": false,
  "issues": [{"field": "tools[0]", "reason": "Tool is not available."}]
}
```

`code` is one of `validation_error`, `duplicate`, `unauthorized`, or
`temporarily_unavailable`. `issues` is required only for validation errors. Created results expose
safe identity/display fields only.

## State Transitions

### Tool invocation

`requested -> validating -> creating -> created`

- Any validation failure: `validating -> error(validation_error)`, no write.
- Existing identity or concurrent loser: `creating -> error(duplicate)`, no overwrite.
- Missing/invalid bound identity: `requested -> error(unauthorized)`, no lookup/write.
- Cosmos failure: `creating -> error(temporarily_unavailable)`, retryable, no claimed success.

### Catalog visibility

After successful create, the record is visible on the owner's next repository/catalog read and to
new sessions. The active session's already-constructed skill provider/tool inventory is not mutated.
